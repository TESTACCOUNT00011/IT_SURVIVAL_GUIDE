# Professionalism Guide

Technical skills get you interviewed. Professionalism gets you hired. This guide covers the non-technical skills that separate amateurs from professionals.

## Building Your Online Presence

### GitHub Profile Setup

Your GitHub is your portfolio. Recruiters will look at it.

**Must-Have Elements:**
1.  **Profile Photo**: Professional headshot or clean avatar
2.  **Bio**: One sentence about what you do and what you're learning
3.  **Pinned Repositories**: Pin your 4-6 best projects
4.  **README Profile**: Create a repository with your username as the name to add a profile README

**Repository Best Practices:**
- Every project needs a README.md explaining what it does
- Include screenshots or GIFs of your project in action
- List the technologies used
- Add installation instructions
- Mention what you learned building it

> [!EXAMPLE]
> Bad README: "My project thing"
> Good README: "A task management app built with React and Node.js. Features include user authentication, drag-and-drop organization, and real-time updates. Built to practice full-stack development."

### LinkedIn Optimization

- Use a professional photo (no selfies, no party pictures)
- Headline: "Aspiring [Role] | Learning [Technologies]"
- Add all projects to the "Featured" section
- Connect with people you meet in communities
- Post small updates about what you're learning

## Resume Basics for Self-Taught Developers

### Structure
1.  **Contact Info**: Name, email, GitHub link, LinkedIn, location (city/state)
2.  **Summary**: 2-3 sentences about your background and goals
3.  **Skills**: Group by category (Languages, Frameworks, Tools)
4.  **Projects**: Most important section for self-taught. Include:
    - Project name
    - Technologies used
    - 2-3 bullet points describing features
    - Link to live demo and GitHub
5.  **Experience**: Include non-tech jobs. Focus on transferable skills
6.  **Education**: Degrees, certifications, relevant courses

### Common Mistakes
- Listing "Microsoft Office" as a skill (assumed)
- Using progress bars for skills (meaningless)
- Including irrelevant hobbies
- Typos and formatting inconsistencies
- Lies about experience level

## Communication Skills

### How to Ask for Help

Bad question: "My code doesn't work. Help?"

Good question format:
1.  What are you trying to accomplish?
2.  What have you tried so far?
3.  What error messages are you seeing? (Copy-paste exact text)
4.  Link to relevant code (GitHub Gist or repository)
5.  What research have you done?

### Email Templates

**Reaching out to a recruiter:**
```
Subject: Application for [Role] - [Your Name]

Dear [Name],

I am writing to express my interest in the [Role] position at [Company]. 
I have been developing my skills in [technologies] through [courses/projects] 
and have built several projects including [brief mention of best project].

My GitHub portfolio showcases my work: [link]

I would welcome the opportunity to discuss how my skills could contribute to your team.

Thank you for your consideration.

Best regards,
[Your Name]
```

**Asking for a referral:**
```
Subject: Quick question about [Company] - [Your Name]

Hi [Name],

I hope you're doing well. I noticed an opening for [Role] at [Company] 
and wanted to ask if you'd be open to sharing any insights about the team culture.

If you feel comfortable after our conversation, I'd appreciate a referral, 
but I completely understand if that's not possible.

Thanks for your time!

Best,
[Your Name]
```

## Interview Preparation

### Technical Interview Types
1.  **Screening**: Basic questions about your background and resume
2.  **Technical Phone**: Coding challenges over phone/video
3.  **Take-Home Assignment**: Build something in your own time
4.  **On-site/Virtual**: Multiple rounds including coding, system design, behavioral

### Behavioral Questions (STAR Method)
Answer using Situation, Task, Action, Result:

- "Tell me about a time you faced a difficult bug"
- "Describe a project you're proud of"
- "How do you handle disagreements in a team?"
- "What's something you taught yourself recently?"

### Red Flags to Avoid
- Blaming others for failures
- Saying "I don't know" without following up with how you'd find out
- Being unable to explain your own projects
- Negative comments about previous employers or teachers

## Networking Without Being Awkward

- **Give before you ask**: Help others, share resources, answer questions
- **Be specific**: Instead of "Can I pick your brain?" ask "Do you have 15 minutes to discuss how you transitioned from X to Y?"
- **Follow up**: Thank people after conversations. Update them on your progress
- **Attend meetups**: Local tech meetups, hackathons, conferences
- **Contribute to open source**: Start small with documentation fixes

## Workplace Etiquette

### First 90 Days
- Listen more than you speak
- Document everything you learn
- Ask questions early, don't spin wheels for days
- Find a mentor (formal or informal)
- Deliver small wins consistently

### Code Review Etiquette
- Don't take feedback personally
- Explain your reasoning when defending decisions
- Thank reviewers for catching issues
- Review others' code thoughtfully
